# Architecture

This document describes the implemented TOML 1.1.0 reader and writer. The
reader returns the native values listed below, and the writer accepts those
same values.

## File layout

The ASDF system loads the shared foundation before the reader and writer.

| Path | Responsibility |
| --- | --- |
| `src/package.lisp` | Defines the public package and exported API. |
| `src/conditions.lisp` | Defines typed parse and encoding conditions. |
| `src/data.lisp` | Defines the native value model and generated predicates. |
| `src/reader-data.lisp` | Defines reader state and character-class tables. |
| `src/reader-macros.lisp` | Defines reader-rule and character-class macros. |
| `src/reader-scan.lisp` | Advances source coordinates and scans lexical spans. |
| `src/reader-path.lisp` | Resolves table paths and document state. |
| `src/reader-values.lisp` | Parses strings, numbers, dates, arrays, and inline tables. |
| `src/reader-document.lisp` | Parses tables, keys, assignments, and documents. |
| `src/reader.lisp` | Provides `parse`, UTF-8 `parse-file`, and source validation. |
| `src/writer-data.lisp` | Defines writer dispatch and output tables. |
| `src/writer-macros.lisp` | Defines writer dispatch macros. |
| `src/writer.lisp` | Provides recursive emission, `encode`, and `write-toml`. |
| `t/conditions-test.lisp` | Tests condition slots and reports. |
| `t/data-test.lisp` | Tests native values, predicates, and value dispatch. |
| `t/fixture-toml-test.lisp` | Loads conformance fixtures and compares values. |
| `t/reader*-test.lisp` | Tests reader values, documents, errors, and conformance. |
| `t/writer-test.lisp` | Tests output validity and unsupported values. |
| `t/roundtrip-test.lisp` | Tests valid fixtures through read and write paths. |

The fixture files under `t/fixtures/` are vendored test data and are not
generated by the reader or writer.

## Public operations

```lisp
(parse source &key source-name)
(parse-file pathname)
(encode value)
(write-toml value stream)
```

`parse` accepts a string or character input stream and returns an equal-tested
hash table. `parse-file` reads UTF-8 bytes and includes the byte position, line,
and column in decoding errors. `encode` returns a string, while `write-toml`
writes directly to a character stream.

## Native values

| TOML kind | Lisp value |
| --- | --- |
| table | equal-tested hash table |
| array | simple vector |
| string | string |
| integer | signed 64-bit integer |
| float | double-float, including SBCL infinity and NaN |
| true | `t` |
| false | `+toml-false+` |
| offset date-time | `cl-date-kit:offset-date-time` |
| local date-time | `cl-date-kit:local-date-time` |
| local date | `cl-date-kit:local-date` |
| local time | `cl-date-kit:local-time` |

`nil` and lists are not TOML values. The declarative definitions in
`src/data.lisp` derive the type declarations, predicates, kind dispatch, and
`toml-value-typecase`. There are no adapter objects for date values.

## Reader and writer control flow

Reader grammar rules are declared with `define-toml-rule`. The macro generates
continuation-passing rules so success, failure, and source coordinates move
through nested TOML constructs without exposing CPS in the public API.

The writer uses ordinary recursion. It walks hash tables and vectors while
emitting directly to the supplied stream. The writer is not CPS because output
ordering and stream effects are already represented by the recursive traversal;
adding heap-escaping continuations would increase allocation and complicate
stream lifetime without improving the interface. Continuations that escape to
the heap must not be declared `dynamic-extent`.

## Conditions and diagnostics

`toml-kit-error` is the root condition. `toml-parse-error` adds source name,
position, line, column, path, expected token, context, and a bounded diagnostic
text excerpt. `toml-encoding-error` reports unsupported values and their path.
Callers should use the exported accessors rather than parse report strings.

## Performance and support

The implementation targets linear work in input length and is SBCL-only. Reader
input is normalized to a simple string and scanned by index. Character classes
are precomputed tables. The writer emits directly to a stream, with `encode`
as the string-output convenience wrapper. No `(safety 0)` or partial optimize
declaration is used.

The conformance suite covers 214 valid and 467 invalid TOML fixtures. Reader,
writer, and round-trip tests are registered with cl-weave; the Nix flake is the
canonical build and test gate. Benchmarks are diagnostic and do not decide
correctness.
